# 宠物社交日记（PetMeet）产品需求文档


## 1 执行摘要

我们正在为18-35岁的年轻单身养宠人群构建一款基于鸿蒙碰一碰能力的宠物社交应用PetMeet，解决养宠人在遛狗、逛宠物店、参加宠物聚会等线下场景中缺乏自然社交破冰方式的问题。通过NFC碰一碰交换宠物名片、建立宠友关系、记录和展示宠物日常，PetMeet将成为鸿蒙生态中首个面对面宠物社交产品。预期上架后30天内获得500+下载，碰一碰日均交换10+次，7日留存率超过30%。


## 2 问题陈述

### 2.1 谁遇到了这个问题
18-35岁的年轻单身养宠人群，居住在一二线城市，使用华为鸿蒙设备，每天有遛狗或出入宠物相关场所的习惯。

### 2.2 问题是什么
养宠人在线下场景中频繁遇到其他养宠人和可爱的宠物，但缺乏自然的社交破冰方式。传统的加微信方式过于私密，直接搭讪显得尴尬；线上宠物社区虽然存在，但缺乏面对面的真实连接感，且充斥大量广告和无关信息。

### 2.3 为什么这是痛点
- 用户影响：大量潜在的宠友关系未能建立，养宠人日常社交需求长期未被满足，遛狗变成一个人的孤独活动
- 情感影响：年轻单身人群本身社交圈有限，宠物本可以成为社交纽带，但缺少合适的工具来连接
- 现有替代方案不足：微信加好友侵入性太强，小红书/抖音宠物社区是陌生人线上互动而非面对面连接

### 2.4 证据
- 中国养宠家庭数量超1亿户，其中独居青年养宠比例逐年上升
- 宠物相关社交需求在小红书上有大量UGC内容验证（"遛狗社交""宠物交友"等话题阅读量过亿）
- 华为应用市场目前无专注线下碰一碰宠物社交的应用，存在生态空白
- 用户典型反馈："每次遛狗遇到可爱的狗狗想认识一下，但开口要微信太尴尬了"


## 3 目标用户与画像

### 3.1 主要画像：社交型养宠青年 Socialite Sam

3.1.1 基本信息
- 年龄：25-30岁
- 居住地：一二线城市
- 职业：互联网/创意行业从业者
- 养宠情况：养1-2只猫或狗
- 手机：华为鸿蒙设备用户
- 社交习惯：活跃于社交媒体，喜欢线下活动

3.1.2 行为特征
- 每天遛狗1-2次，周末去宠物公园
- 喜欢给宠物拍照发社交媒体
- 经常在小区或公园遇到其他养宠人但不知如何搭讪
- 愿意参加宠物线下活动和聚会
- 对新技术接受度高，愿意尝试碰一碰等新交互方式

3.1.3 典型语录
- "每次遛狗遇到可爱的狗狗想认识一下，但开口要微信太尴尬了"
- "小区里好多养宠的人，但除了点头之交没有更深入的联系"
- "想找同品种的狗主人交流养护经验，但线上社区太杂了"

3.1.4 痛点
- 线下遇到宠友缺乏自然的社交破冰方式
- 微信加好友太私密，宠物社区又太线上化
- 想记录宠物成长但不想发朋友圈刷屏
- 换手机后宠物照片和记录容易丢失

3.1.5 目标
- 轻松认识同城宠友，扩大社交圈
- 有一个专属空间记录和展示宠物生活
- 找到同品种/同小区的宠友交流经验

3.2.3 社交性任务
- 当我在宠物聚会上时，我想展示我的宠物信息，以便让别人了解我的宠物
- 当我搬到新小区时，我想快速融入当地养宠圈子，以便获得归属感


## 4 战略背景

### 4.1 业务目标
- 主要目标：成功上架华为应用市场，获得鸿蒙开发者激励计划奖励
- 次要目标：验证碰一碰宠物社交场景的市场可行性
- 长期目标：成为鸿蒙生态中宠物社交品类的标杆应用

### 4.2 市场机会
- 中国宠物市场规模超3000亿元，养宠人群超1亿
- 鸿蒙生态设备数突破5000万台，且仍在快速增长
- 鸿蒙应用市场宠物社交品类为空白，先发优势明显
- 华为对"小而美"的鸿蒙独家应用有明确的流量扶持和编辑推荐政策

### 4.3 竞争格局
- 现有宠物社交应用（如铃铛宠物、有宠等）均为传统线上社区模式，无碰一碰线下社交
- 微信宠物群组分散且信息杂乱
- 小红书/抖音宠物内容为单向展示，非双向社交
- 鸿蒙应用市场无直接竞品

### 4.4 为什么是现在
- 鸿蒙开发者激励计划2025正在进行，上架即可获得奖励
- 碰一碰能力已成熟开放，超过60+应用支持
- 鸿蒙应用市场对独家应用有编辑推荐扶持
- 宠物社交赛道是鸿蒙蓝海赛道之一（医疗健康/社交通讯交叉领域）


## 5 解决方案概述

### 5.1 产品定位
PetMeet是一款基于鸿蒙碰一碰能力的宠物社交应用，核心体验是"碰一碰交换宠物名片"，辅以宠物日记用于社交展示。使用华为账号登录，数据云端同步。

### 5.2 核心用户流程

5.2.1 首次使用流程
启动App → 隐私政策弹窗（同意后继续） → 华为账号一键登录 → 创建第一张宠物名片（上传照片、填写信息） → 进入首页

5.2.2 碰一碰交换流程
打开App显示宠物名片 → 两台设备NFC碰触 → 弹出对方名片预览 → 点击"添加宠友" → 成功提示 → 宠友录新增记录

5.2.3 发布日记流程
点击日记Tab → 点击"+"按钮 → 选择图片（最多9张） → 输入文字 → 选择关联宠物 → 设置公开/私密 → 发布

### 5.3 功能模块

5.3.1 宠物名片模块
- 名片创建：上传宠物照片，填写名字、品种、年龄、性别，选择性格标签（活泼/温顺/胆小/粘人/独立，最多3个）
- 名片展示：卡片式UI，照片占上半部分，信息在下方，性格标签以气泡形式展示
- 名片编辑：随时更新，修改后自动云端同步
- 多宠支持（V1.0仅支持1只，后续版本扩展）

5.3.2 碰一碰社交模块
- 碰一碰交换：调用Share Kit碰一碰分享能力，双方同时发送和接收名片JSON数据
- 交换确认：碰触后弹出对方名片预览，显示"添加到宠友录"和"忽略"按钮
- 交换记录：自动记录时间，可选记录地点（按需申请位置权限）

5.3.3 宠友录模块
- 宠友列表：按添加时间倒序，显示宠物头像、名字、品种、添加时间
- 宠友详情：查看完整名片和公开日记，显示认识时间地点
- 宠友管理：添加备注、删除宠友、拉黑功能

5.3.4 宠物日记模块
- 发布日记：图片（最多9张）+文字，关联宠物，设置公开/私密
- 日记时间线：按时间倒序，图文混排卡片布局，支持按宠物筛选
- 可见性：公开（宠友可见）或私密（仅自己可见）
- 表情反应：宠友可对公开日记发送预设表情（🐾❤️😍🤣👏），每人每篇限选1个

5.3.5 新用户引导任务模块
- 引导任务列表：创建名片后展示，包含完善宠物档案、发布第一篇日记、完成第一次碰一碰
- 任务进度：首页底部以进度条形式展示完成情况
- 任务奖励：完成后解锁对应标识（记录达人/社交先锋），显示在名片上
- 任务完成动画反馈

5.3.6 宠友动态通知模块
- 消息列表：App内通知中心，显示宠友新日记、收到的表情反应
- 红点提示：首页消息入口显示未读红点
- 通知跳转：点击通知直接跳转对应日记详情
- 不使用系统Push通知（避免额外权限申请）

5.3.7 华为账号与云同步
- 华为账号一键登录（Account Kit）
- 宠物资料、宠友录、日记全部云端同步（Cloud DB + Cloud Storage）
- Wi-Fi下自动同步，移动网络手动同步
- 换机后登录自动恢复数据

5.3.8 服务卡片
- 负一屏卡片：显示默认宠物头像和名字、最近日记摘要、宠友数量
- 卡片交互：点击头像进入名片页，点击日记进入详情，点击"+"发布日记

### 5.4 鸿蒙特性利用清单

| 鸿蒙能力 | 应用场景 | 优先级 |
|----------|---------|--------|
| 碰一碰 Share Kit | 交换宠物名片 | P0 |
| 华为账号 Account Kit | 一键登录 | P0 |
| 云数据库 Cloud DB | 数据云同步 | P0 |
| 云存储 Cloud Storage | 图片存储 | P0 |
| 服务卡片 | 负一屏快捷入口 | P1 |
| 意图框架 | 到达宠物公园推荐打开 | P2 |

### 5.5 页面结构
- 启动页：隐私政策弹窗 → 华为账号登录 → 新用户引导任务
- 首页（Tab1）：宠物名片展示 + 碰一碰入口 + 引导任务进度条
- 宠友录（Tab2）：宠友列表
- 日记（Tab3）：日记时间线（含宠友公开日记Feed）
- 消息（Tab4）：宠友动态通知 + 表情反应通知
- 我的（Tab5）：设置、账号管理、隐私政策

### 5.6 数据模型

5.6.1 宠物信息表（Pet）
- petId：String，唯一标识
- userId：String，所属用户
- name：String，宠物名字
- species：String，物种（猫/狗/其他）
- breed：String，品种
- age：Number，年龄
- gender：String，性别（公/母）
- personality：Array<String>，性格标签
- avatar：String，头像图片URL
- createdAt：Timestamp，创建时间
- updatedAt：Timestamp，更新时间

5.6.2 宠友关系表（Friendship）
- friendshipId：String，唯一标识
- userId：String，用户ID
- friendUserId：String，宠友用户ID
- meetTime：Timestamp，碰一碰时间
- meetLocation：String，碰一碰地点（可选）
- remark：String，备注
- status：String，状态（正常/拉黑/删除）
- createdAt：Timestamp，创建时间

5.6.3 日记表（Diary）
- diaryId：String，唯一标识
- userId：String，作者ID
- petId：String，关联宠物ID
- content：String，文字内容
- images：Array<String>，图片URL数组
- visibility：String，可见性（公开/私密）
- createdAt：Timestamp，创建时间

5.6.4 表情反应表（Reaction）
- reactionId：String，唯一标识
- diaryId：String，关联日记ID
- userId：String，反应者ID
- emoji：String，表情类型（paw/heart/love/laugh/clap）
- createdAt：Timestamp，创建时间

5.6.5 通知表（Notification）
- notificationId：String，唯一标识
- userId：String，接收者ID
- type：String，通知类型（new_diary/reaction）
- sourceUserId：String，触发者ID
- relatedDiaryId：String，关联日记ID
- isRead：Boolean，是否已读
- createdAt：Timestamp，创建时间

5.6.6 引导任务表（UserTask）
- taskId：String，唯一标识
- userId：String，用户ID
- taskType：String，任务类型（complete_profile/first_diary/first_bump）
- isCompleted：Boolean，是否完成
- completedAt：Timestamp，完成时间

### 5.7 技术架构
- 前端：ArkTS + ArkUI
- 后端：华为 Cloud DB（Serverless）
- 存储：华为 Cloud Storage 存放图片
- 登录：华为 Account Kit

- 卡片：服务卡片框架

## 7 用户故事与需求

### 7.1 Epic假设
我们认为，为年轻养宠人提供基于碰一碰的宠物名片交换和宠友日记功能，将解决线下宠物社交破冰难的问题，因为现有方式（加微信/线上社区）无法满足面对面轻量社交需求。我们通过审核通过率和碰一碰使用频率来验证。

### 7.2 用户故事

7.2.1 Story 1：创建宠物名片
作为一个新用户，我想创建我的宠物名片，以便通过碰一碰分享给其他宠友。

验收标准：
- 用户可上传1张宠物照片
- 用户可填写宠物名字、品种、年龄、性别
- 用户可选择1-3个性格标签
- 所有字段填写完成后可保存名片
- 保存后名片自动同步到云端
- 名片在首页以卡片形式展示

7.2.2 Story 2：碰一碰交换名片
作为一个已有名片的用户，我想通过碰一碰与另一个用户交换宠物名片，以便互相认识对方的宠物。

验收标准：
- 两台鸿蒙设备NFC碰触后触发名片交换
- 碰触后弹出对方宠物名片预览
- 显示"添加到宠友录"和"忽略"两个操作按钮
- 点击"添加到宠友录"后双方互相加入宠友录
- 交换记录包含时间戳
- 若用户授权位置权限，同时记录交换地点
- 碰一碰失败时显示友好的错误提示

7.2.3 Story 3：管理宠友录
作为一个有宠友的用户，我想查看和管理我的宠友列表，以便回顾和维护宠友关系。

验收标准：
- 宠友列表按添加时间倒序展示
- 每个宠友显示宠物头像、名字、品种
- 点击宠友进入详情页，可查看完整名片
- 可为宠友添加文字备注
- 可删除宠友（二次确认）
- 可拉黑宠友（拉黑后对方无法查看自己的公开日记）

7.2.4 Story 4：发布宠物日记
作为一个用户，我想发布宠物日记，以便记录宠物生活并展示给宠友。

验收标准：
- 可选择1-9张图片
- 可输入文字描述（最多500字）
- 可选择关联的宠物
- 可设置可见性（公开/私密）
- 发布后日记出现在时间线顶部
- 公开日记对所有宠友可见
- 私密日记仅自己可见

7.2.5 Story 5：华为账号登录与数据同步
作为一个用户，我想用华为账号登录并同步数据，以便换机后不丢失信息。

验收标准：
- 首次启动显示隐私政策弹窗，同意后继续
- 支持华为账号一键登录
- 登录后自动创建云端用户档案
- 宠物资料、宠友录、日记自动同步到云端
- Wi-Fi下自动同步，移动网络可手动触发同步
- 新设备登录后自动恢复所有数据
- 提供账号注销功能，注销后删除所有云端数据

7.2.6 Story 6：服务卡片
作为一个用户，我想在负一屏看到宠物信息卡片，以便快速访问应用核心功能。

验收标准：
- 卡片显示默认宠物头像和名字
- 卡片显示最近一条日记摘要
- 卡片显示宠友数量
- 点击宠物头像跳转到名片页
- 点击日记摘要跳转到日记详情
- 点击"+"按钮跳转到发布日记页面
- 卡片数据与App内数据实时同步

7.2.7 Story 7：日记表情反应
作为一个宠友，我想给宠友的日记发送表情反应，以便表达喜爱并让对方获得反馈。

验收标准：
- 公开日记下方显示5个表情按钮（🐾❤️😍🤣👏）
- 每个用户对同一篇日记只能选1个表情（可切换）
- 日记下方显示已收到的表情统计（如🐾3 ❤️5）
- 日记作者在消息Tab收到"XX给你的日记点了🐾"通知
- 自己的日记不显示反应按钮（不能给自己点）

7.2.8 Story 8：新用户引导任务
作为一个新用户，我想在碰一碰之前也有事做，以便不会因为无聊而卸载。

验收标准：
- 创建名片后首页底部显示引导任务进度条
- 任务列表包含3项：
  ① 完善宠物档案（添加生日、体重、更多照片）→ 解锁"档案达人"标识
  ② 发布第一篇日记 → 解锁"记录达人"标识
  ③ 完成第一次碰一碰 → 解锁"社交先锋"标识
- 完成任务后播放庆祝动画
- 标识显示在名片上（宠友碰一碰时可见）
- 3项全部完成后进度条消失

7.2.9 Story 9：宠友动态通知
作为一个用户，我想知道宠友的新动态，以便有理由打开App保持互动。

验收标准：
- 消息Tab显示通知列表，按时间倒序
- 通知类型包含：
  - "[宠物名]的主人发布了新日记" → 点击跳转日记
  - "[宠物名]的主人给你的日记点了❤️" → 点击跳转日记
- 未读通知以红点形式显示在消息Tab图标上
- 红点数字显示未读数量（最多99+）
- 进入消息Tab后自动标记为已读
- 通知保留最近30天，超过自动清理

### 7.3 边界情况与约束

7.3.1 边界情况
- 用户未创建名片时碰一碰：提示先创建名片
- 碰一碰时对方App未打开：提示对方需要打开PetMeet
- 重复碰一碰同一个用户：提示已是宠友，不重复添加
- 网络断开时发布日记：本地缓存，恢复网络后自动同步
- 云端同步冲突：以最新修改时间为准
- 宠友录为空时查看日记Feed：显示空状态引导"去碰一碰认识新宠友"
- 表情反应被拉黑用户：拉黑后对方无法对自己日记发表情
- 通知列表为空：显示空状态"还没有新动态，去发一篇日记吧"

7.3.2 技术约束
- 碰一碰依赖双方设备均支持NFC且运行鸿蒙系统
- Cloud DB免费额度限制：需监控用量，超额提示用户
- 图片存储容量：单张图片压缩至500KB以内
- 服务卡片刷新频率：受系统限制，非实时更新


## 8 范围外（不在V1.0中构建）

8.1 多宠物支持 — V1.0仅支持1只宠物，降低复杂度，验证核心流程后再扩展
8.2 宠友间私信功能 — 避免社交合规审核复杂度，V1.0通过日记展示维持社交
8.3 意图框架场景推荐 — P2优先级，先上架后迭代
8.4 宠物健康记录（疫苗、驱虫等） — 偏向工具属性，与社交定位不符
8.5 附近宠友地图发现 — 涉及实时位置共享，隐私合规风险高
8.6 宠物用品电商/广告 — V1.0保持纯净，不引入商业化
8.7 视频日记 — 增加存储成本和开发复杂度，先验证图文日记
8.8 跨设备协同（平板/智慧屏） — V1.0仅针对手机端


## 9 依赖与风险

### 9.1 依赖项
- 华为Account Kit接入审批（预计1-2个工作日）
- 华为Cloud DB和Cloud Storage服务开通
- Share Kit碰一碰能力开发文档和权限申请
- 至少2台鸿蒙设备用于碰一碰功能测试
- App备案（ICP备案/App备案）

### 9.2 风险与缓解

9.2.1 审核风险：隐私合规不通过
- 概率：中
- 缓解：严格按照华为审核指南实现隐私政策弹窗、权限按需申请、SDK延迟初始化、提供账号注销

9.2.2 技术风险：碰一碰功能不稳定
- 概率：低
- 缓解：提前在真机上测试NFC交换流程，准备碰一碰失败的降级方案（如二维码扫码交换）

9.2.3 用户风险：碰一碰使用门槛高
- 概率：中
- 缓解：首页提供清晰的碰一碰使用引导动画

9.2.4 运营风险：Cloud DB免费额度不足
- 概率：低（早期用户量小）
- 缓解：监控用量，设置告警阈值


## 10 开放问题

10.1 碰一碰失败时是否提供二维码扫码作为降级方案？
- 倾向：V1.0暂不实现，保持碰一碰的独特性，观察失败率后决定

10.2 是否需要内容审核机制？
- 倾向：V1.0日记仅宠友可见（非公开社区），且无评论功能，内容风险低，暂不实现

10.3 宠物品种列表如何维护？
- 倾向：内置常见品种列表（猫50种+狗100种+其他），同时支持用户手动输入

10.4 华为账号注销后数据处理方式？
- 决定：注销后30天内删除所有云端数据，符合个人信息保护法要求

10.5 是否支持鸿蒙元服务形态？
- 倾向：V1.0先以完整App上架，后续可考虑元服务版本

## 12 隐私合规设计

12.1 独立隐私政策文本，首次启动通过弹窗展示，用户同意后方可继续使用
12.2 用户同意隐私政策前不初始化任何SDK（包括Account Kit、Cloud DB）
12.3 位置权限仅在碰一碰场景按需申请，不后台采集
12.4 隐私政策明确说明华为账号数据用途、云同步数据范围、第三方SDK信息
12.5 云端数据传输和存储均加密
12.6 提供完整的账号注销和数据删除功能（注销后30天内清除云端数据）
12.7 从主界面4次以内点击可访问隐私政策（我的Tab → 隐私政策）
12.8 第三方SDK披露清单包含华为Account Kit、Cloud DB、Cloud Storage、Share Kit


## 13 审核风险评估

### 13.1 低风险项
- 功能明确，场景清晰
- 日记仅宠友可见，非公开UGC社区
- 无支付功能、无广告SDK
- 利用多项鸿蒙特有能力，差异化明显

### 13.2 需重点关注
- 隐私政策完整性和SDK延迟初始化
- 位置权限按需申请的实现规范
- 华为账号接入需严格按Account Kit文档实现
- NFC权限使用场景说明
- App备案流程需提前完成

### 13.3 差异化优势
- 碰一碰宠物社交是鸿蒙独有场景，市场无同类竞品
- 结合碰一碰+服务卡片+云同步+华为账号等多项鸿蒙特性
- 聚焦垂直细分场景，符合华为"小而美"应用扶持方向
