# 独立书评影评收藏夹（CultureBox）产品需求文档


## 1 执行摘要

我们正在为文艺青年和文化爱好者构建一款基于鸿蒙碰一碰能力的个人文化收藏应用CultureBox，解决用户想记录和整理自己读过的书、看过的电影、听过的播客、看过的展览，但缺少一个专属空间的问题。提供收藏、评分、短评、标签分类功能，支持碰一碰交换书单/影单/播客单，成为个人文化档案和社交分享工具。预期上架后30天内获得500+下载。


## 2 问题陈述

### 2.1 谁遇到了这个问题
20-40岁的文艺青年、文化爱好者、知识工作者，有阅读和观影习惯，喜欢记录和分享自己的文化消费轨迹，使用华为鸿蒙设备。

### 2.2 问题是什么
用户想记录自己读过的书、看过的电影、听过的播客、看过的展览，但现有方案要么太分散（豆瓣读书/豆瓣电影/小宇宙/小红书各用一个App），要么太公开（发朋友圈/小红书需要顾虑社交形象），缺少一个私密的、整合的、属于自己的文化收藏空间。同时，想和朋友分享推荐时，缺少便捷的交换方式。

### 2.3 为什么这是痛点
- 分散问题：书在豆瓣、电影在豆瓣、播客在小宇宙、展览在小红书，没有一个统一入口
- 私密问题：发朋友圈需要顾虑"是不是显得太装""别人会不会觉得我在炫耀"，无法自由表达真实感受
- 回顾困难：一年下来读了多少书、看了多少电影，没有清晰的统计和回顾
- 分享不便：想给朋友推荐一本书，需要截图或复制链接，步骤繁琐

### 2.4 证据
- 豆瓣读书/电影用户量过亿，证明文化记录需求真实存在
- "年度书单""年度影单"类内容在社交媒体持续流行
- 播客收听量快速增长，但缺少专门的播客收藏工具
- 展览打卡在小红书有大量内容，但缺少个人化的展览档案
- Arrrt（线上美术馆）在鸿蒙创新赛获奖，证明"个人文化收藏"品类受认可

## 4 战略背景

### 4.1 业务目标
- 主要目标：成功上架华为应用市场，获得鸿蒙开发者激励计划奖励
- 次要目标：填补鸿蒙生态"个人文化收藏"品类空白
- 长期目标：成为文艺青年的文化档案首选工具

### 4.2 市场机会
- 文化消费升级，阅读和观影成为生活方式
- 豆瓣用户过亿，但缺少更私密、更整合的替代方案
- Arrrt（线上美术馆）获奖证明"小而美"文化类应用受华为认可
- 碰一碰交换书单/影单是鸿蒙独有体验

### 4.3 竞争格局
- 豆瓣读书/电影：功能完善但公开，缺少私密性
- 小红书：太公开，记录有社交压力
- 微信读书：仅限书籍，无电影/播客/展览
- 小宇宙：仅限播客
- CultureBox差异化：私密整合空间+碰一碰交换+年度回顾

### 4.4 为什么是现在
- 鸿蒙开发者激励计划进行中
- Arrrt获奖后华为对文化类应用有推荐倾斜
- 碰一碰能力成熟，适配书单交换场景
- 年底书单/影单回顾内容流行，时机契合


## 5 解决方案概述

### 5.1 产品定位
CultureBox是一款基于鸿蒙碰一碰能力的个人文化收藏应用，整合书评、影评、播客评论、展览打卡四大品类，提供私密记录、标签分类、年度回顾、碰一碰交换功能。

### 5.2 核心用户流程

5.2.1 添加记录流程
打开App → 点击"+" → 选择类型（书/电影/播客/展览） → 搜索或手动输入信息 → 评分 → 写短评 → 添加标签 → 保存

5.2.2 浏览回顾流程
打开App → 首页时间线/分类浏览 → 点击条目查看详情 → 筛选标签/年份/评分

5.2.3 碰一碰交换书单流程
打开App → 进入"交换"页面 → 选择要分享的内容（书单/影单/播客单/展览单） → 两台设备碰触 → 对方接收书单 → 可查看详情并保存感兴趣的内容

5.2.4 碰一碰推荐单条流程
在条目详情页 → 点击"碰一碰推荐" → 两台设备碰触 → 对方接收该条目完整信息

### 5.3 功能模块

5.3.1 文化条目管理模块
- 条目类型：
  - 书籍：书名、作者、出版社、封面图、阅读日期、评分（1-5星）、短评、标签
  - 电影：片名、导演、年份、海报、观影日期、评分、短评、标签、观看平台
  - 播客：节目名、单集标题、主播、收听日期、评分、短评、标签
  - 展览：展览名、场馆、观展日期、评分、短评、标签、现场照片
- 条目搜索：支持书名/片名/作者/导演等关键词搜索
- 条目编辑：随时修改评分、短评、标签
- 条目删除：支持删除（二次确认）
- 封面/海报：自动从网络获取，支持手动上传

5.3.2 浏览与筛选模块
- 时间线视图：按添加时间倒序展示所有条目
- 分类视图：按书/电影/播客/展览分类浏览
- 标签筛选：点击标签筛选相关条目
- 年份筛选：选择年份查看该年记录
- 评分筛选：查看高分（4-5星）或低分（1-2星）条目
- 统计卡片：显示总数量、本年月度分布、类型占比

5.3.3 年度回顾模块
- 年度统计：
  - 本年阅读XX本书，观影XX部，收听XX期播客，观展XX次
  - 月度分布图表
  - 类型占比饼图
  - 评分分布
  - 最常出现的标签TOP5
- 年度精选：用户手动标记的年度TOP3书籍/电影/播客/展览
- 回顾分享：生成年度回顾长图，可保存或碰一碰分享

5.3.4 碰一碰交换模块
- 交换内容选择：
  - 书单（最近阅读的5本书）
  - 影单（最近观看的5部电影）
  - 播客单（最近收听的5期播客）
  - 展览单（最近观展的3次）
  - 全部（以上所有）
- 交换流程：
  - 选择要分享的内容类型
  - 两台设备NFC碰触
  - 双方同时发送和接收
  - 弹出对方书单预览
  - 可点击条目查看详情
  - 可选择"保存到收藏夹"或"忽略"
- 单条推荐：
  - 在条目详情页点击"碰一碰推荐"
  - 碰触后对方接收该条目完整信息
  - 对方可选择保存或忽略

5.3.5 收藏夹模块
- 收到的书单：保存的他人书单/影单等
- 保存的条目：从他人书单中保存的具体条目
- 添加备注：对保存的条目添加备注（如"朋友推荐，待读"）
- 状态标记：标记为"已读/已看/已听/已去"或"待消费"

5.3.6 华为账号与云同步
- 华为账号一键登录（Account Kit）
- 所有条目数据云端同步（Cloud DB）
- 封面/海报/展览照片云端存储（Cloud Storage）
- 换机后登录自动恢复全部数据
- Wi-Fi下自动同步，移动网络手动同步

5.3.7 服务卡片
- 本月统计卡片：显示本月读了几本书、看了几部电影
- 最近在读书卡片：显示最近在读的书名和进度
- 卡片交互：点击统计卡片进入App首页，点击在读书卡片进入该书详情

### 5.4 鸿蒙特性利用清单

| 鸿蒙能力 | 应用场景 | 优先级 |
|----------|---------|--------|
| 华为账号 Account Kit | 一键登录 | P0 |
| 云数据库 Cloud DB | 条目数据同步 | P0 |
| 云存储 Cloud Storage | 封面/海报/照片存储 | P0 |
| 碰一碰 Share Kit | 交换书单/影单/单条推荐 | P1 |
| 服务卡片 | 本月统计/在读书展示 | P1 |

### 5.5 页面结构
- 启动页：隐私政策弹窗 → 华为账号登录
- 首页（Tab1）：时间线/分类切换 + 添加按钮 + 统计卡片
- 浏览页（Tab2）：分类浏览 + 筛选器
- 年度回顾页（Tab3）：年度统计 + 精选 + 生成长图
- 交换页（Tab4）：碰一碰入口 + 收到的书单
- 我的（Tab5）：标签管理、云同步设置、隐私政策

### 5.6 数据模型

5.6.1 条目表（Entry）
- entryId：String，唯一标识
- userId：String，所属用户
- type：String，类型（book/movie/podcast/exhibition）
- title：String，标题（书名/片名/节目名/展览名）
- subtitle：String，副标题（作者/导演/单集标题/场馆）
- coverUrl：String，封面/海报URL
- date：String，日期（阅读/观影/收听/观展日期）
- rating：Number，评分（1-5）
- review：String，短评（最多500字）
- tags：Array<String>，标签
- platform：String，平台（仅电影：影院/Netflix等）
- photos：Array<String>，展览照片URL数组
- isTopOfYear：Boolean，是否年度精选
- createdAt：Timestamp，创建时间
- updatedAt：Timestamp，更新时间

5.6.2 标签表（Tag）
- tagId：String，唯一标识
- userId：String，所属用户
- name：String，标签名称
- count：Number，使用次数
- createdAt：Timestamp

5.6.3 收到的书单表（ReceivedList）
- listId：String，唯一标识
- userId：String，接收者用户ID
- senderId：String，发送者用户ID
- senderName：String，发送者昵称
- listType：String，类型（book/movie/podcast/exhibition/all）
- entries：Array<Object>，条目列表（快照）
- meetTime：Timestamp，交换时间
- createdAt：Timestamp

5.6.4 保存的条目表（SavedEntry）
- savedId：String，唯一标识
- userId：String，所属用户
- sourceListId：String，来源书单ID
- entryData：Object，条目完整数据（快照）
- status：String，状态（pending/done）
- remark：String，备注
- createdAt：Timestamp

### 5.7 技术架构
- 前端：ArkTS + ArkUI
- 后端：华为 Cloud DB（Serverless）
- 存储：华为 Cloud Storage 存放封面/海报/照片
- 登录：华为 Account Kit
- 交换：Share Kit 碰一碰
- 卡片：服务卡片框架
- 封面获取：调用豆瓣API或自建封面库（需确认版权）

## 7 用户故事与需求

### 7.1 Epic假设
我们认为，为文艺青年提供私密整合的文化收藏空间和碰一碰交换书单功能，将解决文化记录分散和分享不便的问题，因为现有方案要么太公开要么太分散。我们通过审核通过率和条目添加量来验证。

### 7.2 用户故事

7.2.1 Story 1：添加文化条目
作为一个文化爱好者，我想记录我读过的书、看过的电影、听过的播客、看过的展览，以便建立个人文化档案。

验收标准：
- 支持添加4种类型条目（书/电影/播客/展览）
- 每种类型有对应的字段（书名/作者/出版社等）
- 支持评分（1-5星）
- 支持写短评（最多500字）
- 支持添加标签
- 自动从网络获取封面/海报（失败时可手动上传）
- 保存后自动云端同步

7.2.2 Story 2：浏览和筛选条目
作为一个有大量记录的用户，我想按分类、标签、年份、评分筛选浏览，以便快速找到想回顾的内容。

验收标准：
- 时间线视图：按添加时间倒序展示
- 分类视图：按书/电影/播客/展览分类
- 标签筛选：点击标签显示相关条目
- 年份筛选：选择年份显示该年记录
- 评分筛选：筛选高分或低分条目
- 搜索：按书名/片名/作者等关键词搜索
- 统计卡片：显示总数量和类型占比

7.2.3 Story 3：生成年度回顾
作为一个喜欢在年底总结的用户，我想生成漂亮的年度回顾，以便回顾一年的文化消费轨迹。

验收标准：
- 自动统计本年读了几本书、看了几部电影等
- 生成月度分布图表
- 生成类型占比饼图
- 生成评分分布
- 显示最常出现的标签TOP5
- 用户可手动标记年度TOP3
- 可生成长图保存或分享

7.2.4 Story 4：碰一碰交换书单
作为一个喜欢和朋友分享推荐的用户，我想通过碰一碰交换书单/影单，以便发现共同兴趣和获取推荐。

验收标准：
- 可选择交换内容类型（书单/影单/播客单/展览单/全部）
- 两台设备NFC碰触后交换
- 弹出对方书单预览，可点击条目查看详情
- 可选择"保存到收藏夹"或"忽略"
- 保存后可在"收到的书单"中查看
- 碰一碰失败时显示友好提示

7.2.5 Story 5：碰一碰推荐单条
作为一个想推荐具体作品的用户，我想碰一碰发送单条条目给朋友，以便对方收到完整信息。

验收标准：
- 在条目详情页点击"碰一碰推荐"
- 碰触后对方接收该条目完整信息
- 对方可选择"保存到收藏夹"或"忽略"
- 保存时自动标记为"待消费"状态

7.2.6 Story 6：管理收到的书单和保存的条目
作为一个收到朋友推荐的用户，我想管理收到的书单和保存的条目，以便跟进阅读/观看计划。

验收标准：
- 收到的书单按时间倒序展示
- 可查看书单详情和条目列表
- 可选择保存单个条目到收藏夹
- 可添加备注（如"朋友推荐，待读"）
- 可标记状态（待消费/已完成）
- 可删除书单或条目

7.2.7 Story 7：华为账号与云同步
作为一个用户，我想我的文化档案自动云端同步，以便换手机后不丢失记录。

验收标准：
- 华为账号一键登录
- 所有条目数据自动云端同步
- 封面/海报/照片云端存储
- 换机登录后自动恢复全部数据
- 提供账号注销功能

### 7.3 边界情况与约束

7.3.1 边界情况
- 封面/海报获取失败：显示占位图，提示手动上传
- 碰一碰时对方未安装CultureBox：提示"对方需要安装CultureBox"，显示下载引导
- 条目数量过多：分页加载，每页20条
- 年度回顾无数据：提示"今年还没有记录，快去添加吧"
- 碰一碰交换重复条目：自动去重，不重复保存

7.3.2 技术约束
- 封面/海报依赖外部API（豆瓣等），需确认版权和稳定性
- 碰一碰NFC传输数据量限制，书单条目控制在10条以内
- Cloud DB免费额度需监控
- 年度回顾长图生成受Canvas性能限制


## 8 范围外（不在V1.0中构建）

8.1 社区/广场（公开分享和发现） — 避免UGC社区审核复杂度，保持私密属性
8.2 评论和点赞功能 — 避免社交功能复杂度
8.3 音乐/演出品类 — 增加开发量，先验证核心4品类
8.4 餐厅/美食记录 — 偏离文化定位
8.5 OCR识别书籍封面自动添加 — 增加开发量
8.6 阅读进度追踪（读了多少百分比） — 专注记录而非追踪
8.7 跨设备协同（平板/智慧屏浏览） — V1.0仅手机端


## 9 依赖与风险

### 9.1 依赖项
- 华为Account Kit接入审批
- 华为Cloud DB和Cloud Storage服务开通
- Share Kit碰一碰能力接入
- 封面/海报数据源（豆瓣API或自建库，需确认版权）
- 至少2台鸿蒙设备用于碰一碰测试
- App备案

### 9.2 风险与缓解

9.2.1 内容风险：封面/海报版权问题
- 概率：中
- 缓解：使用豆瓣开放API（如允许）或引导用户手动上传；在隐私政策中说明图片来源

9.2.2 审核风险：被归类为"简单记录工具"
- 概率：中低
- 缓解：强调碰一碰交换书单功能（鸿蒙独有），强调年度回顾功能，与豆瓣形成差异化

9.2.3 增长风险：冷启动阶段内容少
- 概率：中
- 缓解：引导用户从豆瓣导入（手动或截图OCR），提供快速添加体验

9.2.4 技术风险：封面API不稳定
- 概率：中
- 缓解：本地缓存封面，API失败时提示手动上传


## 10 开放问题

10.1 封面/海报数据来源？
- 倾向：优先使用豆瓣开放API（需确认接口稳定性），备选方案为用户手动上传

10.2 是否支持从豆瓣导入？
- 倾向：V1.0不支持自动导入（涉及数据抓取合规），提供手动快速添加体验

10.3 碰一碰交换的书单条目数量？
- 倾向：默认最近5条，用户可选择最近3/5/10条

10.4 年度回顾长图的样式？
- 倾向：提供2-3种模板选择（简约/文艺/数据可视化）

10.5 是否支持导出数据？
- 倾向：V1.0支持导出为JSON格式，方便用户备份或迁移

## 12 隐私合规设计

12.1 独立隐私政策文本，首次启动弹窗展示，用户同意后方可继续
12.2 用户同意前不初始化任何SDK
12.3 存储权限仅在上传图片场景按需申请
12.4 所有文化记录属于用户个人数据，云端加密存储
12.5 隐私政策明确说明云端数据范围、第三方SDK信息
12.6 提供账号注销功能，注销后30天内删除所有云端数据
12.7 从主界面4次以内点击可访问隐私政策
12.8 第三方SDK披露清单包含Account Kit、Cloud DB、Cloud Storage、Share Kit


## 13 审核风险评估

### 13.1 低风险项
- 功能明确，工具属性清晰
- 无UGC社区，无公开内容审核风险
- 无支付功能，无广告
- 碰一碰交换是鸿蒙独有体验

### 13.2 需重点关注
- 与豆瓣的差异化需在应用描述中强调
- 封面图片来源需合规
- 碰一碰功能需明确说明用途

### 13.3 差异化优势
- 私密整合空间（书+电影+播客+展览）
- 碰一碰交换书单/影单是鸿蒙独有体验
- 年度回顾功能满足年底总结需求
- Arrrt获奖后华为对文化类应用有推荐倾斜
- 与豆瓣形成互补而非竞争（私密vs公开）
